# 维护约定

知识正文放在 `docs/`；项目记忆只记录维护决策、入口和会话变更。

- `session_notes.md`：按日期记录完成了什么，不充当完整聊天记录。
- `topics_index.md`：稳定主题的入口。
- `topics/`：一文件一主题，记录范围、依据和后续边界。

用户要求落文档、整理进仓库时，即视为本次内容保存授权。对于未要求保存的多轮技术讨论，可以询问是否整理；得到确认后更新正文、索引和日期记录。

2026-11-20，用户确认：围绕用代码制作视频的交流中，形成的结论，以及值得留下的做法、边界和验证结果，可以直接写入本知识库，不必每次再单独询问。已有指南覆盖的内容只补差异，不另写复述。新的稳定结论写入 `docs/` 的指南或案例；维护决定写入 `project_context/`。

后续需要实际测试、渲染或运行检查脚本时，使用用户的 `llm_new` 环境。该名称是本机约定，不写入对外技术指南当作通用依赖。

新增内容优先扩展已有指南。工具版本和命令只有在有证据时才标为实测；案例引用原工程路径须说明该工程是否包含在仓库中。

多人协作时，一条片子做成 `example/<案例名>/` 案例项目。说明写在项目内，过程音频、静帧、成片和检查图跟说明放在一起。`.gitignore` 对 `example/` 取消音视频忽略。模型权重、原始下载音源和本机绝对路径脚本不作为可移植工程提交。案例项目里的 `render-stable.sh` 一类文件只保留当时记录。
