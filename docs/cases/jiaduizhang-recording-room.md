# 贾队长《慌啥子嘛，慢慢来》视频制作技术说明

文档整理日期：2026 年 11 月 19 日
对应作品：`贾队长-慌啥子嘛-鼎香楼录音室.mp4`（未随本仓库发布）
依据：本地制作脚本、模型推理代码、项目规格、生成参数、检查报告与渲染日志。

## 1. 这条视频是怎么做出来的

这条视频将“贾队长的角色音色”“《慌啥子嘛》的副歌演唱”和“鼎香楼系列的像素角色动画”组合起来：先让贾队长清唱一句“慌啥子嘛，慢慢来”，停顿后，再带伴奏重新演唱副歌。画面中，角色戴监听耳机，在鼎香楼内部布置的录音室里演唱，配合张嘴、眨眼、扶耳机、身体摇摆以及镜头切换。

制作的主体流程是：先处理歌曲音频并进行 AI 歌声转换，再生成可拆分的像素素材，最后通过 HTML/CSS 和 JavaScript 编排画面，由 HyperFrames 渲染成 MP4。声音生成、画面绘制和视频渲染是几个独立环节，依靠统一时间轴衔接。

| 成片项目 | 实际规格 |
| --- | --- |
| 画幅 | 9:16 竖屏，1080 × 1920 |
| 帧率 | 24 fps |
| 工程时长 | 36.3 秒 |
| MP4 容器时长 | 36.334 秒，来自本次 ffprobe 核对 |
| 视频编码 | H.264 |
| 成片音频 | AAC，48 kHz，双声道 |
| 像素场景基础尺寸 | 270 × 480，基础布局按 4 倍显示 |
| 核心声线模型 | Seed-VC，44.1 kHz、带 F0 条件的歌声转换模型 |
| 动画与渲染 | Pillow + HTML/CSS + GSAP + HyperFrames 0.9.65 |

工程时长和容器时长略有不同，是音视频帧粒度与封装边界需要区分的两个口径；视频并未因此多出一段内容。

## 2. 整体制作链路

```text
歌曲音源 + 贾队长单人参考音频
                  │
                  ▼
Demucs 人声/伴奏分离 → 截取 31.8 秒副歌
                  │
                  ▼
RMVPE 音高分析 → Seed-VC 换成贾队长音色、降低 5 个半音
                  │                         │
                  │                    伴奏同步降调
                  └───────────┬─────────────┘
                              ▼
                 FFmpeg 人声处理、混音、响度控制
                              │
                 ┌────────────┴─────────────┐
                 ▼                          ▼
       成片播放音轨                    独立清唱驱动音轨
       清唱→静音→伴奏版                 提取 RMS 包络
                 │                          │
                 │                          ▼
                 │                    固定嘴形切换数据
                 │                          │
Pillow 像素场景/人物 PNG ────────┬─────────────┘
                               ▼
                  HTML/CSS 分层 + GSAP 动画
                               │
                  五个镜头 + 歌词字幕时间轴
                               ▼
                   HyperFrames 浏览器逐帧渲染
                               ▼
                     H.264/AAC MP4 成片
```

AI 主要承担声音转换；像素美术由脚本绘制，角色动作由时间轴控制。项目文件没有体现使用文生视频、真人数字人或神经网络逐音素对口型来生成这条画面。

## 3. 素材准备与版本选择

### 3.1 最终使用的是哪一版声音

工作区里保留了“慢慢来”“慌啥子嘛音色加强”“赵本山底版”等多个历史目录。最终录音室视频的 `BRIEF.md` 明确记录，使用已认可的“赵本山底版降调翻唱”。因此，本说明以该版为主，不把早期候选参数混写进最终流程。

原歌曲音轨为 `reference_audio/慌啥子嘛-赵本山-B站音源.m4a`。同名 `.source.json` 保存了来源 URL、页面标题、上传者和下载信息。这里的“赵本山版”沿用第三方页面的署名，音源是压缩音频，并非官方无损母带。

角色参考使用 `reference_audio/贾队长-单人长参考音频.wav`，约 20.99 秒。这份单人参考同时也是此前《隐形的翅膀》转换文件所标记的参考，便于跨作品对照。

### 3.2 为什么选择干净的单人参考

参考音频提供的是目标角色的音色线索。多人对白、背景音乐和明显噪声会使提取到的说话人特征更复杂；本项目选择单人长参考，目的是让模型更稳定地获得贾队长的音色条件。

参考音频不需要先唱出这首歌。歌曲里的歌词、演唱节奏和旋律走向主要由源演唱提供；参考音频主要提供“换成谁的声音”。源演唱中的咬字和唱法仍可能影响转换结果。

## 4. 音频制作：从原歌到贾队长翻唱

### 4.1 Demucs：把歌曲分成人声和伴奏

使用 Demucs 的 `htdemucs` 模型处理全曲，保存两条音轨：

- `vocals.wav`：分离出来的原演唱人声，作为换声输入。
- `no_vocals.wav`：分离出来的伴奏，作为后续混音底轨。

分离后，从两条对应音轨中截取 63.8–95.6 秒，共 31.8 秒副歌。两条音轨采用相同裁切区间，保证转换后的人声能与伴奏对齐。

先分离再换声，可以减少乐器对模型的干扰，并允许人声、伴奏分别调音量和音高。混音脚本只主动加入“转换后人声 + 分离伴奏”，没有主动把原唱人声混回去；但分离算法可能在伴奏里留下少量残留，不能把 `no_vocals` 理解为绝对纯净。

### 4.2 Seed-VC：保留歌曲内容，转换目标音色

本项目使用预训练 Seed-VC 模型，加载的主权重为：

```text
DiT_seed_v2_uvit_whisper_base_f0_44k_bigvgan_pruned_ft_ema_v2.pth
```

制作脚本执行的是基于参考音频的推理，没有训练或微调一个专属“贾队长模型”。其主要模块在本次任务中的作用如下。

| 模块 | 在本项目中的作用 |
| --- | --- |
| Whisper 编码器 | 从输入音频提取内容特征，为转换提供歌词发音等信息；这里使用编码特征，不直接输出字幕 |
| RMVPE | 提取 F0，也就是声带振动对应的基频轨迹，为歌声音高控制提供条件 |
| CAMPPlus | 从参考音频提取说话人音色特征；另外也用于生成结果的辅助相似度比较 |
| DiT / 条件流匹配生成模块 | 结合内容、音高、参考音色等条件，生成转换后的声学表示 |
| BigVGAN 声码器 | 把生成的声学表示还原成可播放的音频波形 |
| PyTorch / CUDA | 承担模型加载和 GPU 推理 |

可以将转换任务理解为：尽量保留原演唱唱了什么、何时唱、音高怎样起伏，同时让生成声音向贾队长参考的音色靠近。实际效果仍取决于原演唱、参考质量、音域和生成参数。

### 4.3 实际使用的推理参数

| 参数 | 实际值 | 用途 |
| --- | --- | --- |
| 输出模型采样率 | 44.1 kHz | 带 F0 条件的歌声转换路径 |
| `diffusion_steps` | 20 | 控制生成迭代步数，影响耗时与生成表现 |
| `inference_cfg_rate` | 0.8 | 调节条件引导强度，不代表音色相似度百分比 |
| `length_adjust` | 1.0 | 保持原有时长比例，方便与伴奏对齐 |
| `f0_condition` | true | 启用音高条件 |
| `auto_f0_adjust` | false | 关闭自动基频整体对齐，使用明确的半音移调 |
| `semi_tone_shift` | 最终候选为 −5 | 将人声音高整体降低 5 个半音 |
| `fp16` | true | 推理脚本启用半精度选项 |
| 随机种子 | 20261118 | 固定 Python、NumPy、PyTorch 随机状态，减少候选比较中的随机变化 |
| 模型运行环境 | 用户的 `llm_new` | 遵循工作区环境要求 |
| GPU | 物理 GPU 1 | 脚本通过 `CUDA_VISIBLE_DEVICES=1` 选择 |

固定随机种子有助于复查和比较，但不保证跨硬件、跨依赖版本的输出逐样本一致。历史说明还记录，缺失辅助包通过已有 Seed-VC venv 的 site-packages 补充，主运行环境保持为 `llm_new`。

### 4.4 为什么降低 5 个半音

前期反馈指出，旧《慌啥子嘛》版本角色感不够明显。重做时使用 RMVPE 分析音高，统计大于 65 Hz 的帧，得到：

| 对比对象 | F0 中位数约值 |
| --- | --- |
| 赵本山底版副歌人声 | 287.08 Hz |
| 贾队长说话参考 | 193.23 Hz |
| 旧《隐形的翅膀》转换成品 | 191.32 Hz |

脚本以旧《隐形的翅膀》转换成品的基频中位数为目标线索，按下面的关系估算半音差，并将范围限制在 −5 到 +5：

```text
半音差 = round(12 × log2(目标基频 / 源基频))
降调后的基频 = 原基频 × 2^(−5/12)
```

降低 5 个半音的频率倍率约为 0.749，287 Hz 因而会落到约 215 Hz。这里通过整体移调保留旋律相对起伏，同时尝试让演唱声区更接近角色的中低声区。该处理是候选优化依据，不能仅凭基频就证明角色音色问题的全部原因。

人声降调后，伴奏也用 FFmpeg 的 `rubberband` 滤镜降低相同的 5 个半音，保持歌曲调性一致，并保持播放时长。

### 4.5 人声清理、混音与响度控制

`混音核对.py` 使用 FFmpeg 完成以下处理：

| 处理 | 脚本中的关键设置 | 目的 |
| --- | --- | --- |
| 人声时长统一 | `apad`、`atrim=duration=31.8` | 补齐或裁切到目标时长 |
| 低频清理 | `highpass=f=70` | 减少低频隆隆声等干扰 |
| 人声淡入 | 0.03 秒 | 缓和开头边界 |
| 尾部淡出 | 从 31.55 秒开始，持续 0.25 秒 | 让结束更平顺 |
| 人声响度归一化 | `I=-17:TP=-2:LRA=9` | 控制响度与峰值目标 |
| 伴奏电平 | 乘以 0.72 | 为人声留出空间 |
| 人声伴奏合成 | `amix`，`normalize=0` | 按已有电平直接混合 |
| 最终混音响度 | `I=-16:TP=-1.5:LRA=9` | 控制成品响度与峰值目标 |
| 音频输出 | WAV，另导出 192 kbps MP3 | 留存编辑音频与试听版本 |

`I` 表示综合响度目标，`TP` 表示真峰值目标，`LRA` 表示响度范围参数。以上为滤镜配置；它们不等于另一次独立测量报告中的实测值。

## 5. 开场清唱与伴奏进入的设计

完整配乐时间轴分为三段：

| 时间 | 声音内容 | 作用 |
| --- | --- | --- |
| 0–3.95 秒 | 开头一句清唱 | 先突出角色音色 |
| 3.95–4.5 秒 | 静音停顿 | 给伴奏进入留出节奏空间 |
| 4.5–36.3 秒 | 完整 31.8 秒副歌混音 | 从所选副歌开头重新演唱 |

因此，带伴奏的第一句会再次唱“慌啥子嘛，慢慢来”，这是既定编排。清唱段使用独立人声，不靠把带伴奏歌曲简单降低音量来模拟。

音频目录同时保存成片混音、开场清唱和 `口型驱动-清唱.wav`。播放音轨负责最终听感；清唱驱动音轨负责嘴形分析。后者避免鼓点或其他乐器的强音量被当成“角色正在唱歌”。

历史核看记录通过样本比对确认开场清唱、静音与后续混音的结构；本次整理也复核了现存文件规格，未重新生成声音。

## 6. 像素画面的制作技术

### 6.1 Pillow 程序化绘制

场景和人物 PNG 主要由 Python 的 Pillow 库绘制。`Image` 创建画布，`ImageDraw` 用矩形、多边形、线条、圆弧等图元构建形状，`ImageFont` 加载中文字体生成招牌文字。

录音室美术沿用此前《贾队长解梦》的鼎香楼系列：暖木墙面、灯笼、青绿色窗棂、茶具、瘦脸贾队长和深色外套。在这个基础上添加耳机、吸音板、麦克风、防喷罩、磁带录音机、调音台和监听音箱，使其成为鼎香楼里的一间录音室。

人物造型直接复用旧工程 `生成像素素材.py` 的 `person('jia')`，再补画裤腿、鞋子、耳机和扶耳机手臂。这种做法让同一系列沿用相同的脸型、发型和服装基础，而不需要每次重新生成角色。

### 6.2 为什么先画小尺寸，再放大

场景的基础画布是 270 × 480，对应最终 1080 × 1920 的四倍尺寸。CSS 设置 `image-rendering: pixelated`，使像素放大时保持方块边缘，避免常规平滑插值把画面变糊。

四倍关系是基础场景的显示比例；镜头还叠加 1.32、1.40、1.55 等缩放，因此并非每个镜头始终都是整数倍率。项目的风格来自低分辨率绘制和像素化显示共同作用。

### 6.3 图层如何拆分

| 图层或素材 | 内容与用途 |
| --- | --- |
| `客栈录音室.png` | 木梁、窗、灯笼、吸音板、地毯及设备底图 |
| `jia-normal-closed.png` / `open.png` | 普通姿态的闭嘴、张嘴角色 |
| `jia-ear-closed.png` / `open.png` | 扶耳机姿态的闭嘴、张嘴角色 |
| `麦克风.png` | 带透明背景的麦克风、防喷罩、支架和连线 |
| HTML/CSS 元素 | 眨眼覆盖层、转动磁带盘、电平显示、录音灯与字幕 |

分层让角色可以独立摇摆、切换嘴形和手势，也让麦克风处于前景遮挡位置。镜头缩放时，场景中的相关元素仍能一起移动。

## 7. 声音驱动嘴形与角色动画

### 7.1 用 RMS 包络决定何时张嘴

`制作.py` 读取独立清唱驱动音轨，以每秒 12 次的频率取样，每个窗口约 83.3 毫秒。每个窗口计算 RMS，并保存到 `assets/activity.json`，数值保留四位小数。

```text
RMS = sqrt(mean(音频样本²))
```

RMS 可以粗略反映这段人声的能量。`编排.py` 再按以下规则生成嘴形切换：

```text
RMS > 0.027，并且窗口编号不是 4 的倍数：显示张嘴图
否则：显示闭嘴图
```

额外插入的闭嘴窗口让长音期间也有开合变化。仅在嘴形状态发生变化时，脚本才写入一次 GSAP `tl.set()`，最终得到固定、可定位到时间点的动画数据。

这是声音能量驱动的两状态嘴形，适合当前像素风格；它没有识别每个音素，也没有生成“啊、哦、衣”等不同嘴型。人声驱动数据以 12 Hz 更新，而成片画面以 24 fps 输出，两者不必完全相同。

### 7.2 为什么预先计算，而不是播放时随机变化

嘴形先分析再写进时间轴，渲染到某一时间点时就能直接得到对应状态。这样截图、跳转预览和多个浏览器 worker 渲染都使用相同的动作安排，不依赖当时的实时麦克风或音频分析状态。

### 7.3 其他动作的实现

| 动作 | 技术方式 |
| --- | --- |
| 身体小幅摇摆 | GSAP 在约 0.75 秒周期内改变 y 位移与约 0.4° 旋转，`sine.inOut` 往返 |
| 眨眼 | 在各镜头内的指定时间点显示眼部覆盖层，约 0.12 秒后恢复 |
| 扶耳机 | 切换到预绘制的 `ear` 姿态素材 |
| 磁带盘转动 | CSS 图形配合 GSAP 旋转动画，约 3.2 秒一圈 |
| 设备电平变化 | GSAP 改变图形横向缩放，采用阶梯式节奏 |
| 录音红灯闪烁 | GSAP 改变不透明度 |

只有嘴形由清唱包络数据驱动。磁带盘、设备电平和红灯等是预设装饰动画，不应描述成每一个设备都在实时分析声音。

## 8. 分镜、字幕与网页时间轴

### 8.1 五个镜头的编排

本片主要通过同一套分层场景的缩放、平移和姿态切换形成不同景别。

| 时间范围 | 镜头设计 | 场景缩放约值 |
| --- | --- | --- |
| 0–4.5 秒 | 清唱近景，扶耳机 | 1.55 |
| 4.5–12.28 秒 | 伴奏进入，切回录音室全景 | 1.00 |
| 12.28–19.76 秒 | 人物中近景 | 1.32 |
| 19.76–27.18 秒 | 再次扶耳机，构图偏移 | 1.40 |
| 27.18–36.3 秒 | 回到较完整的全景结束 | 1.02 |

这些镜头不是五段重新生成的视频，也不是完整三维摄影机运动，而是同一像素场景的不同构图。

### 8.2 HTML/CSS 与 GSAP 分别做什么

HTML 负责承载场景、人物图片、字幕和音轨；CSS 负责尺寸、层叠顺序、字体、颜色及像素显示方式；GSAP 负责规定各元素在时间轴上的状态变化。

根入口为 `project/index.html`，下挂 `intro.html`、`room.html`、`verse.html`、`refrain.html`、`end.html` 和 `lyrics.html` 等子合成。每个合成声明起始时间、持续时长及轨道，GSAP 时间轴以暂停形式创建，并注册到 `window.__timelines`，供渲染器按时间定位。

工程中，场景使用图形轨，歌词使用字幕轨，成片混音使用音频轨。字幕独立于镜头存在，所以切换景别时不需要复制整套歌词。

### 8.3 字幕是如何同步的

字幕共 9 个显示区间：清唱开场 1 句，加上正式副歌 8 句。正式副歌的所有歌词时间统一加 4.5 秒，和伴奏进入点对齐。

当前 `编排.py` 直接保存每句的开始、结束时间，因此最终画面是按句显示，并非逐字卡拉 OK 高亮。音频工作目录另有转写时间文件，但不能据此认定成片字幕全部由 ASR 自动生成；最终采用的时间与文本，以字幕编排脚本为准。

字幕采用本地中文字体、浅金色字、深棕背景和边框，顶部位置约在 y=1128，左右布局为平台按钮区预留空间。文字作为独立 HTML 层，在画面合成时输出到成片。

## 9. HyperFrames 如何把网页变成视频

HyperFrames 将 HTML 动画工程作为视频源，在浏览器中定位时间轴并捕获对应帧，再完成编码与音画封装。

项目最终固定使用 0.9.65 版本，渲染日志记录了以下过程：

1. 编译入口与子合成，确定尺寸、时长和资源。
2. 探测浏览器和音频，准备渲染环境。
3. 采用 `beginframe` 捕获模式，启动 4 个 worker 处理画面。
4. 按 24 fps 捕获并编码 872 帧。
5. 合并音频，输出 H.264/AAC MP4。
6. 验证生成的文件并输出渲染结果。

日志标记浏览器 GPU 为启用状态，并记录 `hardware gpu`。这能说明当次使用的渲染路径，但不足以进一步断言最终编码器一定使用了 NVENC 或某种特定硬件编码器。

历史日志显示，当次渲染约耗时 37.3 秒，其中画面捕获阶段约 31.5 秒，捕获与编码存在重叠。该时间只对应视频渲染，未包含音源下载、分离、AI 换声、美术制作和迭代检查的总耗时。

## 10. 制作过程中的检查与实际局限

### 10.1 音色的辅助比较

使用 CAMPPlus 提取说话人嵌入，对不同候选进行余弦相似度比较。历史记录如下：

| 候选 | 与贾队长长参考的相似度 | 与旧《隐形的翅膀》转换成品的相似度 |
| --- | --- | --- |
| 旧音色加强版 | 0.7602 | 0.8004 |
| 新原调版 | 0.8242 | 0.8607 |
| 新降 5 半音版 | 0.8562 | 0.9054 |

这些数字支持把降调版作为优先试听候选，但不代表“85.62% 还原贾队长”。说话人嵌入会受音域、唱法和录音条件影响，最终角色感仍由试听判断。视频需求记录写明沿用已认可的降调版；制作脚本的自动检查本身没有人耳验收能力。

### 10.2 音频文件检查

混音脚本检查样本是否全部为有限数值、时长是否达标，以及峰值是否小于数字满幅。降调候选的清唱和混音 WAV 都为 31.8 秒，混音样本峰值约 0.6693，未达到满幅削波。

历史成片核对还记录了：

- MP4 完整解码通过。
- 成片音轨与源混音的相关系数约为 0.99942。
- 4.05–4.4 秒停顿窗口的 RMS 为 0。

这些是已有核看记录中的结果，本次文档整理没有重新执行完整音频对比或人工听音验收。

### 10.3 画面与工程检查

历史 HyperFrames `check-result.json` 显示总体通过，运行、布局、对比度和音频等检查无错误；保留 1 条 `timeline_track_too_dense` 警告，原因是 9 句歌词集中在同一个字幕子合成中，便于连续编辑。

报告中的 motion 专项检查实际为关闭状态，不能把所有标记 `ok` 的栏目都理解为执行了完整动态检测。对比度检查记录为 15 项通过。历史人工画面核看还修正了扶耳机姿态残留的下垂手臂，并调整了字幕和角标位置。

本次整理通过 ffprobe 重新确认：成片为 1080 × 1920、24 fps、H.264，音频为 AAC 48 kHz 双声道，容器时长 36.334 秒。

### 10.4 当前方案的边界

当前方案适合做风格统一、可编辑、制作成本较低的像素音乐短视频。嘴形只有开合两种状态，角色只有有限手势，镜头主要靠同一场景的构图变化。因此它能表现“角色在唱歌”，但还达不到逐音素精确口型、完整肢体表演或三维多视角的效果。

后续可以增加不同口形、真正的侧面角色、更多手势及更细的歌词对齐；这些属于可改进方向，并非本版已经使用的技术。

npm run dev
npm run check
npm run render

## 13. 对外介绍时可以这样表述

这条《贾队长：慌啥子嘛，慢慢来》短视频，采用了 AI 歌声转换与程序化像素动画相结合的制作方式。音频部分先用 Demucs 分离歌曲的人声和伴奏，再通过 Seed-VC 参考贾队长的单人音频进行换声，并结合音高分析选择降低五个半音的版本，伴奏同步降调后完成混音。画面部分用 Python 绘制鼎香楼系列的像素场景与人物，通过独立人声的能量包络驱动简化嘴形，用 GSAP 编排眨眼、摇摆、扶耳机和五个镜头的构图变化，最后由 HyperFrames 将 HTML 动画工程渲染为带歌词字幕的竖屏 MP4。整个项目保留了音频中间结果、素材生成脚本和可编辑视频工程，便于后续替换歌曲并延续系列风格。
