# 国风鼎香楼视频持续闪烁排查记录

记录日期：2026-11-19。案例：代码绘制的贾队长《慌啥子嘛》国风鼎香楼版。

## 问题现象

用户反馈“怎么是一闪一闪的”“一直在闪，感觉像是在放幻灯片”。检查实际导出的MP4连续帧，确认正常画面之间周期性夹入大片底色条带及黑块，而不是正常镜头切换。不是通过添加转场或增加人物动作解决的问题。

## 工程与触发条件

- 原生SVG绘制角色与场景，GSAP控制动画，HyperFrames 0.9.65本地浏览器渲染。
- 1080×1920，24 fps，36.334秒，共872帧，H.264/AAC。
- 原导出日志：`captureMode=beginframe`、`browserGpuMode=auto`，实际采用hardware GPU，3个worker。
- 静态预览截图正常，MP4能完整解码，均不能证明连续画面正确。

## 定位依据与结论边界

从实际MP4解码连续帧，观察到正常帧之间反复出现大面积未绘制区域。原文件低分辨率逐帧检测发现290帧存在大面积空白或局部缺失，285处非预期切点的大幅画面跳变。

保持SVG、GSAP动画与音轨不变，仅将导出方式改为完整截图、单worker和软件浏览器合成，先导出2秒试片，再导出整片，问题消失。因此可将故障定位到原浏览器画面捕获/合成流程。由于捕获方式、worker数与GPU模式同时改变，没有单独隔离底层驱动或并发条件，不能认定是某个GPU驱动的确定缺陷，也不能断言所有HyperFrames GPU渲染都会闪烁。

## 已验证的修复方式

使用已安装HyperFrames技能提供的 `scripts/plugin-cli.mjs` 启动器，在视频工程目录执行：

```sh
# 将 /path/to/hyperframes 替换为已安装技能的实际目录。
node /path/to/hyperframes/scripts/plugin-cli.mjs render . \
  --fps 24 --quality delivery \
  --low-memory-mode --no-browser-gpu \
  -o ../贾队长-慌啥子嘛-国风鼎香楼-修复闪烁版.mp4
```

修复日志确认 `forceScreenshot=true`、`browserGpuMode=software`、`workerCount=1`。工程中已保存 `project/render-stable.sh`，后续可复用。修复保留原有口型、眨眼、手势和镜头运动，没有用静态图片替换动画。

## 验证结果

| 检查项 | 原文件 | 修复版 |
| --- | --- | --- |
| 总帧数 | 872 | 872 |
| 大面积空白或部分缺失帧 | 290 | 0 |
| 非切点异常大幅跳变 | 285 | 0 |
| 相邻帧平均绝对差，RGB 0–255尺度 | 21.6873 | 0.6421 |
| 完整解码 | 通过，但仍存在视觉问题 | 通过 |

修复版仍为1080×1920、24 fps、36.334秒。音轨与源素材的相关系数为0.999392；4.05–4.4秒停顿区间RMS为0。人工查看原坏帧位置和切点附近的连续帧拼图，画面完整。没有直接试听，音频结论仅来自数据核对。

检测脚本将每帧缩至108×192，计算相邻帧平均绝对差；对本片排除4.5、12.28、19.76和27.18秒切点前后两帧范围，差值超过15视为异常候选。另以横向像素标准差筛查大面积近乎纯色条带。此阈值针对本片慢速二维动画，快速打斗、闪光和其他构图需要重新设置，不能作为通用画质评分。

## 后续交付要求

1. 在本机同类工程中优先使用已验证的稳定导出脚本；更换捕获方式或运行环境后先导出短片检查。
2. 检查实际MP4的连续帧和正常速度播放效果，不能只核看HTML预览或离散截图。
3. 完整解码、画面连续性、音轨核对分开验证；文件没有解码错误不代表画面没有坏帧。
4. 保存原片与修复片、日志、检测报告和连续帧对照图，保留异常位置以便回归。
5. 完成结论必须依据新导出的文件，不以旧截图或旧检查结果替代。
